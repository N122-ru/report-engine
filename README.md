# Конструктор отчётов по ГОСТ 7.32

Приложение для подготовки, проверки и экспорта учебных и научных отчётов по
ГОСТ 7.32-2017 и ГОСТ 2.105-2019: лабораторных (ЛР), практических (ПР),
расчётно-графических (РГР), курсовых работ (КР) и проектов (КП), НИР,
контрольных работ и отчётов по учебной, производственной и преддипломной практике.
Можно указать свой вид работы. Вуз, институт и кафедра заполняются пользователем;
встроенный логотип СамГТУ можно заменить своим или отключить.

Работать в редакторе можно без ИИ. Для помощи агента нужен отдельный MCP-клиент:
приложение не содержит собственной нейросети. Версия отображается в интерфейсе
и доступна через `/api/version`; история изменений публикуется в GitHub Release проекта.

## Какой вариант выбрать

| Вариант | Для чего | Что требуется |
| --- | --- | --- |
| Веб из исходников (dev web) | Работа с исходниками, редактор и живой MCP | Python, Node.js и npm |
| Переносимый веб (standalone web) | Редактор в браузере и живой MCP на своём компьютере | Готовый пакет для своей ОС и браузер |
| Переносимый MCP (standalone headless) | Работа агента без браузера и HTTP-сервера | Готовый пакет и MCP-клиент с поддержкой stdio |
| Образ Docker | Редактор и сервис целиком в контейнере, включая офисный конвертер и шрифты (PDF из коробки) | Docker и архив образа из GitHub Release |

Переносимые пакеты предусмотрены для Linux x64 (сборка на Ubuntu 22.04) и
Windows x64. Они **содержат Python runtime и зависимости**, но не требуют
установленных Python, pip, Node.js или исходников. Пакеты не включают офисный
конвертер и системные шрифты для документов; браузерные шрифты формул входят в web.
Готовые архивы берите из GitHub Releases проекта, если выпуск уже опубликован.

## Возможности

- Оформление DOCX: поля 30/15/20/20 мм, Times New Roman 14 pt, полуторный
  интервал, абзацный отступ 1,25 см и автоматическая нумерация страниц.
- Титульный лист с несколькими студентами и преподавателями, логотипом или
  режимом без логотипа. Имена указываются в формате «И.О. Фамилия».
- Markdown-редактор с формулами LaTeX, таблицами, листингами и изображениями.
- Предпросмотр А4, проверка структуры и нормоконтроль DOCX, предупреждения
  о неприкреплённых рисунках и исправление типографики.
- Список литературы: книги, статьи, сайты и стандарты; ссылки на источники в тексте.
- Шаблоны дисциплин и перенос профиля через JSON.
- Сохранение полного проекта в JSON вместе с прикреплёнными изображениями.

Предпросмотр оценивает расположение страниц, но не заменяет проверку готового
DOCX/PDF. Нормоконтроль выявляет поддерживаемые нарушения, а не гарантирует
соответствие всем требованиям преподавателя.

## Быстрый старт: переносимый веб

1. Распакуйте весь архив `report-engine-web-v<версия>-<платформа>.zip`
   в доступную для записи папку. Не отделяйте исполняемый файл от `_internal`.
2. В Windows запустите `start-web.bat`; в Linux — `./start-web.sh`.
   Если Linux сообщает об отсутствии права запуска:
   `chmod +x start-web.sh report-engine-web`.
3. Дождитесь открытия браузера или откройте напечатанный адрес вручную:
   по умолчанию <http://127.0.0.1:8000>.
4. Заполните титульник, выберите вид работы, добавьте текст и изображения,
   проверьте предпросмотр и нормоконтроль, скачайте DOCX.
5. Для резервной копии выберите **«Файл» → «Сохранить проект (.json)»**.
   Остановите сервер через `Ctrl+C`, когда работа закончена.

Сервер доступен только на этом компьютере. Оставляйте его терминал открытым.
Текст и реквизиты сохраняются в хранилище браузера, изображения — в IndexedDB;
очистка хранилища может удалить их. Другой браузер или другой адрес/порт имеет
отдельное хранилище — для переноса используйте JSON.

## Быстрый старт: веб из исходников

Нужны Python 3.11+ и Node.js, совместимый с текущим Vite
(рекомендуется Node.js 22.12+), а также npm. Команды выполняются из корня проекта:

```bash
./start.sh
```

Откройте <http://localhost:5173>; API работает на порту 8000.
Скрипт при необходимости устанавливает зависимости. `./start.sh prod` собирает
SPA и запускает единый сервер на <http://localhost:8000>; это запуск из исходников,
не переносимый пакет. Остановка — `Ctrl+C` или `./start.sh stop`.
Также доступен `python3 start.py`. Документация API: <http://localhost:8000/docs>.

## Быстрый старт: Docker

1. Скачайте архив `report-engine-docker-image-v<версия>-linux-x64.tar.gz` из
   GitHub Releases проекта.
2. Загрузите образ в Docker:

   ```bash
   docker load -i report-engine-docker-image-v<версия>-linux-x64.tar.gz
   ```

   После загрузки образ получает тег `report-engine:v<версия>`.
3. Запустите контейнер:

   ```bash
   docker run -d --name report-engine -p 8000:8000 report-engine:v<версия>
   ```

4. Откройте <http://localhost:8000>.
5. Для остановки и удаления контейнера выполните:

   ```bash
   docker stop report-engine
   docker rm report-engine
   ```

MCP для Docker подключается так же, как для web-варианта: сервис в контейнере
доступен на порту 8000. Откройте редактор и используйте инструкцию из окна
**«ИИ-агент (MCP)»**; отдельная настройка headless-сервера для этого запуска не нужна.
Для обычной работы используйте промпт `write_report`, а при первом подключении
клиентского агента для постоянной работы — `agent_onboarding`: агент сам изучит
окружение и заведёт локальную памятку с разделом «Клиентские оптимизации», дополняя
его опытом после каждой сессии. Анкета не нужна: максимум один короткий вопрос,
только если неясно, разовая работа или постоянная. Для разовой работы памятка
не создаётся; при неизвестном режиме агент продолжает без дополнительных вопросов.
Памятка на сервере не сохраняется.

В отличие от ZIP-пакетов, в образ уже включены LibreOffice и шрифты. Times New Roman
устанавливается через `msttcorefonts`; если пакет недоступен, используются метрически
совместимые Liberation/DejaVu. Поэтому экспорт PDF работает без установки офисного
пакета на компьютере. Образ собирается автоматически при публикации релиза.

Вручную собрать образ из исходников можно командой `docker build .`. Node.js и npm
на компьютере для этого не нужны: frontend собирается внутри multi-stage Dockerfile.

## Быстрый старт: headless MCP

1. Распакуйте весь headless-архив и создайте папку для готовых файлов,
   например `output` внутри пакета.
2. В MCP-клиенте выберите транспорт **stdio**, команду — полный путь к
   `report-engine-headless` (Linux) или `report-engine-headless.exe` (Windows).
   Аргументы: `--output-dir` и полный путь к существующей папке вывода.
3. Переподключите сервер. Попросите агента прочитать `report://rules/gost732`,
   создать отчёт через `create_report` либо загрузить профиль через `import_profile`,
   затем заполнить разделы, вызвать `lint_report` и явно экспортировать DOCX.

Пример настройки для Windows; замените пути на свои:

```json
{
  "mcpServers": {
    "report-engine": {
      "command": "C:\\ReportEngine\\report-engine-headless.exe",
      "args": ["--output-dir", "C:\\ReportEngine\\output"]
    }
  }
}
```

В Linux используйте пути вида `/path/to/package/report-engine-headless` и
`/path/to/package/output`. Формат настроек зависит от MCP-клиента.
Лаунчер `start-headless.bat` / `start-headless.sh` предназначен также для ручного
запуска: ожидание клиента в консоли не означает зависание и не открывает браузер.

Один процесс ведёт один отчёт в RAM. Перед остановкой явно вызовите
`export_report`: имя файла задаётся без пути, существующие файлы не перезаписываются.
Агент должен получить свежие `revision`, `meta_revision` и `image_revision`
через `get_report_state` перед экспортом. При остановке черновик и изображения теряются.
В standalone агент может передать путь к изображению через `file_path` вместо base64.

## Подключение агента к веб-редактору

Этот способ одинаков для веба из исходников, Docker и переносимого web:

1. В шапке нажмите **«ИИ-агент (MCP)»**.
2. На вкладке **«Команда агенту»** скопируйте инструкцию в чат своего агента.
   Ему нужны поддержка SSE и права настройки MCP; обычного чата без инструментов недостаточно.
3. Агент подключается к адресу вида `/api/mcp/sse?token=...`, читает
   `report://rules/gost732`, затем получает `get_report_state` перед правками.
4. Если автоматическая настройка недоступна, используйте вкладки **«SSE URL»**
   или **«JSON»** того же окна и переподключите клиент вручную.
5. Оставляйте сервер и вкладку редактора открытыми. При устаревшем токене
   скопируйте новую инструкцию. Не публикуйте адрес с токеном.

Агент может читать рисунки, править разделы и реквизиты, запускать нормоконтроль.
Запоздалые записи отклоняются; конфликт реквизитов или текста нужно разрешить
в интерфейсе, а не перезаписывать вслепую. Web использует **SSE**, headless — **stdio**;
`report-engine-web` нельзя подключать как stdio-сервер.

## Перенос профиля

Профиль переносит **одну дисциплину и реквизиты титульника**, а не весь отчёт:
учебное заведение, город, студентов, преподавателей, вид и номер работы,
год, режим логотипа, кафедру, указания преподавателя и последний номер работы
в шаблоне. Текст, изображения отчёта, тема, библиография и настройки размещения
в профиль не входят. Для полного отчёта используйте сохранение проекта.

Формат — UTF-8 JSON: `format: "report-engine-profile"`, `version: 1`,
объекты `subject` (шаблон дисциплины) и `meta` (реквизиты). Максимум — 4 МБ.
Файл называется `profile-<дисциплина>.json` с латинским именем; не меняйте
маркер формата и версию вручную. Профиль содержит персональные реквизиты:
перед передачей другому человеку проверьте содержимое.

- **Веб → веб:** выберите **«Файл» → «Экспортировать профиль (.json)»**,
  затем в другом варианте, браузере или на другом компьютере —
  **«Файл» → «Импортировать профиль (.json)»**. Импорт добавляет и выбирает
  шаблон, применяет реквизиты; текущие текст и изображения не заменяются.
  Сначала завершите синхронизацию и разрешите конфликт реквизитов, если он есть.
- **Веб → headless:** передайте JSON агенту или сохраните файл локально.
  Попросите вызвать `import_profile` с `profile` (объект JSON) **или**
  `file_path` (путь на машине MCP-сервера), но не с обоими параметрами.
  Первый импорт создаёт отчёт; для уже созданного нужен
  `expected_meta_revision` из свежего `get_report_state`.
- **Через живой MCP:** тот же `import_profile` применяет профиль к открытой
  веб-сессии и всегда требует свежий `expected_meta_revision`.
  Передача объекта удобнее, если файл не находится на машине сервера.

Рекомендуется импортировать профиль в headless **до** заполнения отчёта:
импорт заново формирует реквизиты, а поля вне профиля получает из значений
по умолчанию. Текст и прикреплённые изображения остаются. Пользовательский
логотип для headless должен быть встроенным `data:image/...;base64,...`,
не путём к файлу; действуют дополнительные ограничения размера.
В headless нет отдельного инструмента экспорта профиля: сохранённый JSON можно
повторно импортировать в веб, но изменения реквизитов в RAM не обновляют этот файл.

## DOCX, PDF и шрифты

DOCX не требует офисного конвертера. PDF — дополнительная возможность:
приложение ищет `soffice`/`libreoffice` либо ONLYOFFICE Document Builder
(`docbuilder`) и проверяет ответ на запрос версии. Статус и тип конвертера
доступны через `/api/capabilities` в веб-варианте.

Если установленный конвертер не найден, можно указать путь к нему переменной
`REPORT_ENGINE_PDF_CONVERTER`. `REPORT_ENGINE_DISABLE_PDF=1` отключает PDF.
Успешная проверка версии ещё не гарантирует правильную конвертацию:
проверьте итоговый файл и доступность Times New Roman на своей машине.

Если PDF недоступен, экспортируйте DOCX и сохраните его в PDF вручную через
Microsoft Office, LibreOffice или OnlyOffice. Переносимые пакеты не скачивают
конвертеры и не устанавливают шрифты во время работы.

## Docker

Нужен Docker Compose. Из корня проекта запустите контейнер:

```bash
docker compose up --build -d
```

Это альтернатива запуску готового образа из релиза, описанному в разделе
«Быстрый старт: Docker».

Откройте <http://localhost:8000>. Остановка — `docker compose down`.
В отличие от переносимых архивов, текущий Dockerfile устанавливает LibreOffice
и шрифты при сборке; Node.js в готовом образе не нужен. Установка Microsoft-шрифтов
может завершиться с предупреждением и заменой на Liberation/DejaVu — проверьте
PDF и журналы сборки. Compose публикует порт 8000, поэтому это не loopback-only
режим standalone web; ограничьте сетевой доступ средствами своего окружения.

## Проверка обновлений

Проверка GitHub Releases встроена и не отправляет телеметрию. По умолчанию приложение
проверяет репозиторий `N122-ru/report-engine`; отдельная настройка не нужна. Для
другого репозитория или JSON-ленты задайте один из параметров до запуска:

```bash
export REPORT_ENGINE_UPDATE_REPOSITORY=owner/repository
# Или укажите URL JSON-ленты.
export REPORT_ENGINE_UPDATE_URL=https://api.github.com/repos/owner/repository/releases/latest
```

Для Docker переменную можно передать перед командой Compose:

```bash
REPORT_ENGINE_UPDATE_REPOSITORY=owner/repository docker compose up --build -d
```

Если репозиторий пока приватный, GitHub недоступен или сети нет, проверка получает
нейтральный статус «недоступна» и приложение продолжает работать без сообщений об
ошибке. После публикации `N122-ru/report-engine` проверка начнёт получать его релизы
автоматически. Обновления не скачиваются и не устанавливаются; после переноса проекта
достаточно изменить адрес источника переменной окружения.

## Если что-то не работает

- **Web не запускается:** распакуйте архив целиком, проверьте ОС/архитектуру
  и сообщения терминала. Папка `_internal` должна оставаться рядом с бинарником.
- **Порт занят:** остановите предыдущий сервер или запустите
  `start-web.bat --port 8001` / `./start-web.sh --port 8001`.
  Откройте новый адрес и заново скопируйте инструкцию MCP; хранилище браузера
  на другом порту будет отдельным.
- **Браузер не открылся:** откройте напечатанный URL вручную. Автооткрытие
  зависит от PowerShell в Windows или графической сессии и средств открытия URL в Linux.
- **Headless ждёт:** настройте его запуск из MCP-клиента с транспортом stdio;
  обычный текст в консоли не является MCP-запросом.
- **MCP не подключается:** проверьте транспорт, пути и папку вывода для headless;
  для web — работающий сервер, открытую вкладку и актуальный токен.
- **Профиль не импортируется:** проверьте, что это профиль версии 1, а не полный
  проект, файл меньше 4 МБ и конфликт реквизитов разрешён.
- **DOCX сообщает об отсутствующем XML/шаблоне:** распакуйте актуальный пакет
  заново, не заменяйте отдельные файлы `_internal` вручную.
- **Нет PDF или отличается вёрстка:** проверьте конвертер и шрифты либо используйте
  ручной экспорт из DOCX.
- **Антивирус блокирует запуск:** проверьте источник пакета и сообщение защиты;
  не отключайте её вслепую. Проверка на всех антивирусах не проводилась.

Подробная инструкция прилагается как `README.md` внутри каждого архива.
Технические ограничения и проверенность выпуска: [`RELEASE_STATUS.md`](RELEASE_STATUS.md).
Инструкции для сопровождающих по сборке и выпуску: [`release_tools/README.md`](release_tools/README.md).
